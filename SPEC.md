# Рядом 2.0 — ТЗ

## Цель

Городское PWA для жителей Севастополя: чаты домов и СНТ, заявки с фото и статусом,
карта, проверенные специалисты, участковые. Продукт продаётся управляющим компаниям,
ТСЖ и администрациям — значит нужен реальный многопользовательский режим, роли
сотрудников и сохранность данных.

Версия 1.0 (vanilla JS + JSON-файл) сохранена в `legacy-v1/` как референс UI и логики.

## Критерий приёмки (продукт можно продавать, если)

1. Данные живут в PostgreSQL (Supabase) и **не теряются** при перезапуске инстанса —
   проверяется перезапуском dev-сервера и повторным чтением записи.
2. Фото заявки хранится в Supabase Storage, в БД только путь. Тело запроса ≤ 5 МБ,
   фото ≤ 3 МБ, тип JPEG/PNG/WebP проверяется и на клиенте, и на сервере.
3. Сессия — httpOnly + Secure + SameSite=Lax cookie, токен в БД хранится хешем
   (sha256), есть выход и истечение (60 дней). Пароли — scrypt с солью.
4. Роли: `resident`, `uk_manager`, `moderator`, `admin`. Статус заявки меняет автор
   или сотрудник (`uk_manager`/`moderator`/`admin`). Проверяется тестом.
5. Rate limit логина и регистрации работает между инстансами (таблица в БД).
6. `npm run build` и `npm run typecheck` зелёные; `npm test` покрывает пароли,
   валидацию, права на смену статуса.
7. Есть SQL для Supabase (`supabase/0001_init.sql` + `supabase/0002_seed.sql`) и
   инструкция: GitHub → Supabase → Vercel → перенос на свой сервер.
8. Перенос на свой сервер = смена `DATABASE_URL` + S3-эндпоинта, без правки кода.

## Стек

- **Next.js 15** (App Router), **TypeScript** (strict), React 19.
- **Drizzle ORM** + `postgres` (SQL-first, миграции в git, без vendor lock-in).
- **Supabase** только как managed Postgres + Storage (S3-совместимый).
  Авторизация — своя, чтобы переезд не требовал переписывать аккаунты.
- Валидация — **zod** (одна схема на сервере).
- Стили — существующие CSS-токены и компоненты из v1 (дизайн сохраняем),
  CSS Modules для новых частей.
- Деплой — **Vercel**; альтернатива — VPS/Timeweb + Docker.

## Архитектурные решения

| Решение | Почему |
|---|---|
| Не берём Supabase Auth | Переезд на свой сервер = миграция пользователей. Свои сессии = `pg_dump` и всё |
| Не берём Prisma | Drizzle ближе к SQL, миграции читаемы, старт на serverless дешевле |
| Убираем localStorage-режим | Дублировал всю бизнес-логику (388 строк) и расходился с сервером |
| Чат: incremental polling по курсору | Realtime Supabase требует anon-ключа на клиенте и RLS-политик; polling каждые 4 с по `after` даёт тот же UX без утечки доступа |
| Фото в Storage, не base64 | base64 в БД раздувает базу и каждый ответ API |

## Границы (не входит в этот этап)

- Push-уведомления, SMS-подтверждение, оплата.
- Модерация контента и жалобы (роль `moderator` есть, UI модерации — позже).
- Мобильные приложения в сторах.
