## Решения

- 2026-10-22 — v1.0 перенесена в `legacy-v1/` (не удалена).
- 2026-10-22 — Supabase используется как Postgres + Storage (S3 API); авторизация своя.
  Причина: переезд на свой сервер = `pg_dump` + смена `DATABASE_URL`, без миграции аккаунтов.
- 2026-10-22 — убран локальный режим на localStorage: он дублировал API (388 строк)
  и расходился с сервером (валидация статусов, счётчики).
- 2026-10-22 — Tailwind не вводим: дизайн-система v1 (`styles/`) переиспользована,
  миграция классов дала бы регрессии без выгоды.
- 2026-10-22 — две корневые раскладки (`app/(landing)`, `app/(main)`) вместо одного
  layout: у лендинга и приложения конфликтующие глобальные стили (`body`, `.wrap`).
- 2026-10-22 — схема БД без расширений: `citext` заменён на `text` + уникальный
  индекс `lower(email)`. Работает на Supabase, Timeweb, RDS и PGlite.
- 2026-10-22 — rate limit в таблице + SQL-функция `hit_rate_limit` (атомарный upsert).
  In-memory счётчик на serverless не работает вовсе.
- 2026-10-22 — фото в S3 через `aws4fetch` (один код для Supabase/MinIO/R2/AWS),
  а не `@supabase/supabase-js`: иначе переезд требовал правки кода.
- 2026-10-22 — чат на инкрементальном опросе (`?after=`) раз в 4 с вместо
  полного `/bootstrap` каждые 30 с. Realtime отложен: требует anon-ключа на клиенте.

## Технические заметки

- 2026-10-22 — `npm run dev` теперь самодостаточен: без `DATABASE_URL` поднимает
  PGlite на 5433+ (данные в `.pglite-data/`), применяет миграцию и сид, затем
  запускает Next.js. Раньше без `.env` приложение отдавало 500 на `/api/bootstrap`.
- 2026-10-22 — ошибки БД отделены от прочих: нет `DATABASE_URL` и недоступная
  база → 503 с понятным текстом (`DatabaseNotConfiguredError` в `lib/env.ts`,
  проверка кодов ECONNREFUSED/ENOTFOUND в `lib/http.ts`).
- 2026-10-22 — **драйвер заменён: postgres.js → node-postgres (`pg`)**. На проекте
  Supabase (pooler `aws-1-eu-central-1`) postgres.js рвал сокет после 2–4 запросов,
  `pg` держится заметно лучше. Замеры на той же базе:
  одно соединение выдерживает ~7 запросов, 8-й висит; ответы > ~50 КБ не доходят;
  новые соединения при этом открываются нормально (20/20).
- 2026-10-22 — из-за этого лимита `/api/bootstrap` схлопнут в **один** SQL
  (`json_build_object`), карточка заявки — тоже один запрос вместо трёх.
  Было 8 запросов на страницу — ровно на границе обрыва.
- 2026-10-22 — в `lib/db/index.ts` добавлены `query_timeout`/`statement_timeout`
  (15 с) и один повтор на свежем соединении для сетевых ошибок
  (`ECONNRESET`, `ENOENT`, `EAI_AGAIN`, таймаут). Причина: сеть до AWS во Франкфурте
  периодически отдаёт ENOENT по DNS и рвёт соединения; HTTPS при этом работает.
- 2026-10-22 — повтор сначала работал только для сырого SQL, а `getCurrentUser`
  и записи шли через query builder и падали с `Connection terminated unexpectedly`.
  Теперь **все** обращения к базе идут через `withDb()` (обёртка с повтором),
  прямой `getDb()` в маршрутах не используется.
- 2026-10-22 — пул закрывает простаивающие соединения сам (5 с) и держит TCP
  keep-alive: Supavisor закрывает сокеты раньше, и пул отдавал «мёртвые».
  Это и давало 503 через 12–15 с ожидания.
- 2026-10-22 — `npm run db:reset-limits` — сброс лимитов входа (12 попыток / 10 мин),
  чтобы не блокировать себя при тестировании.
- PGlite socket server держит одно соединение → в dev/e2e задаётся `DB_POOL_MAX=1`.
  На Supabase пул 3–5, это норма для serverless.
- `postgres.js` работает с `prepare: false` — обязательно для transaction pooler
  Supabase (pgbouncer), иначе подготовленные запросы рвутся между запросами.
- PowerShell 5.1 при `Set-Content -Encoding UTF8` добавляет BOM и может перекодировать
  файл. Правки файлов с кириллицей — только через write/edit, не через replace в PS.
- 2026-10-22 — проверка **живой базы Supabase**: 14 таблиц public, все колонки по
  схеме, RLS включён на всех 14, функция `hit_rate_limit` и бакет `request-photos`
  на месте, демо-аккаунт `anna@example.com` с ролью admin. Сид идемпотентен:
  повторный прогон `0002_seed.sql` по стейтментам (37/37 ✓) не изменил счётчики
  (16 домов, 22 сообщения, 5 заявок, 2 пользователя, 10 событий).
- 2026-10-22 — ошибка `42703 column "building_id" does not exist` из SQL Editor
  **не воспроизводится**: и схема, и сид проходят на живой базе. Похоже на остаток
  более ранней попытки/другой копии файла.
- 2026-10-22 — **локальный канал до Supabase рвёт крупные ответы**: `select
  repeat('x', N)` — 8–12 КБ доходят, 15–64 КБ висят до таймаута. Воспроизводится на
  портах 6543 и 5432, на всех трёх IP балансировщика, без TLS тоже; HTTPS на 1 МБ с
  той же машины качается нормально. Это не база и не код: `/api/bootstrap` (~14 КБ)
  локально отдаёт 500 `Query read timeout`. На Vercel (другая сеть) требует проверки
  живым запросом.
